Lattice

Clash-free weekly class timetables for a whole college

uselattice.app

Ankur Paul

Lattice builds a weekly class timetable for a whole college, with no teacher, section or room booked twice. It's live at uselattice.app and works without an account.

The problem

Today

Most colleges still make the timetable by hand in a spreadsheet. It takes days, and one change, like a teacher leaving, can cause clashes across a dozen sections.

With Lattice

Enter the week, rooms, teachers, sections and courses, then click Generate timetable. A solver finds the best timetable it can, and a separate checker confirms nothing is booked twice.

How it’s built

Browser · Cloudflare Pages

React + TypeScript app

  • Four-step guided flow, saved in the browser
  • Quick-draft heuristic in a Web Worker, for when the server is down
  • Validator re-checks every result against H1–H8
  • Scorer computes S1–S5 for both engines

Solver · AWS Lambda, Mumbai

FastAPI + OR-Tools CP-SAT. Finds the best timetable, or proves none exists and says why.

Assistant · AWS Lambda

Claude answers questions and proposes changes as cards. Teacher names leave the browser as codes.

Supabase · Mumbai

Sign-in, institutes and roles under row-level security, saved versions, public links.

Lattice · 3

The browser does the checking: whichever engine made a timetable, the same TypeScript validator and scorer judge it. The server is one Docker image that runs as two Lambda functions. Deploys run from GitHub Actions after CI passes, then a smoke check runs; a rollback workflow redeploys an older commit.

The rules a timetable follows

Hard rules · never broken

  • A teacher, a section and a room are each in one class at a time (H1–H3)
  • The room type and department fit the class (H4)
  • Every class is placed once, or listed with a reason (H5)
  • A lab fills consecutive periods, never across a break (H6)
  • Nothing is placed in a break (H7)
  • Every section and teacher gets a free lunch period each day (H8)

Soft rules · points, lower is better

RulePoints
Same subject twice in a day (S1)10 per extra lecture
Teacher teaching over 3 in a row (S2)5 per period
Free periods between classes (S3)2 per period
A batch idle during another’s lab (S4)3 per period
Free periods before the day’s last class (S5, off by default)1 per period

Each soft rule can be switched off under Aims.

Lattice · 4

Hard rules decide whether a timetable is valid; soft rules decide which valid timetable is best. The sample college's best score is 18, all of it from batches waiting during labs.

  • Each subject has its own colour, and a lab spans its periods
  • Batch labs (B1, B2) stack in one cell; 🍽 marks the lunch candidates

How to test it

Five minutes, no account

  1. Open uselattice.app
  2. ② Add data → Load sample
  3. ③ Generate → Generate timetable. It takes about 20 s; the first run after the server idles takes longer.
  4. ④ View & export → switch views, drag a class, lock one and Regenerate, Print

The Excel files hold the data, not the week. In a fresh browser, click Load sample once first so step 1 has the sample week, then upload a file in step 2. The folder's README says what each file should show.

Step ① · Setup week

Set up the week

  1. Tick the working days
  2. Generate periods from a start time, length, count and break, or edit each row
  3. Mark the periods where lunch may fall

How it’s designed

Every section and teacher gets one of the marked periods free each day (H8). The solver picks which one, so lunch can move to fit the classes.

Lattice · 7

Load sample fills this step too: Monday to Friday, eight periods, a break after P2, lunch candidates P4 to P6.

Step ② · Add data

Add the college’s data

  1. Load sample, or download the Template and fill it in
  2. Choose file to upload the .xlsx, or one CSV per sheet
  3. Check the summary and edit any table in place

How it’s designed

Checks run as you edit. A class with no eligible room blocks Next; a teacher or room booked past the week gets a warning.

Lattice · 8

Rooms can be shared or owned by a department, and a section can split into lab batches, each with its own lab teacher. The tables open in dependency order: departments, rooms, teachers, sections, courses.

Step ② · Add data

Import errors by row

  1. Upload broken-import.xlsx
  2. Read the red card: each problem names the sheet, the row and the bad value
  3. Fix those rows and upload again

How it’s designed

A file with any error imports nothing, so a half-loaded college never reaches the solver. A valid file asks before it replaces the data.

Lattice · 9

The three errors: Rooms row 4 has type "hall"; Courses row 5 names a teacher "Sharma" who isn't in the Teachers sheet; Courses row 8 has "three" as lectures per week.

Step ③ · Generate

Generate with the exact solver

  1. Click Generate timetable; it runs for up to 20 s
  2. Read the card: the score and the points per rule
  3. Try longer: 40 s if the best wasn’t proved in time

How it’s designed

CP-SAT finds the best timetable or proves none exists. The browser then re-checks the result with its own validator and scores it again.

Lattice · 10

If the solver server is offline, the button becomes Make a quick draft, which runs a heuristic in the browser. There is no silent fallback: the quick draft only runs from a button that says so.

Step ③ · Generate

When no timetable exists

  1. Upload cannot-be-built.xlsx and Generate
  2. Read the causes, most likely first
  3. The fix button opens step ② filtered to that teacher
  4. Or Make a partial timetable: it places what fits and lists the rest

How it’s designed

The solver proves it impossible, and the app names the cause with numbers: 42 periods a week, only 35 free.

Lattice · 11

Causes come from the solver's diagnosis (classes with no slot, locks that can't hold) plus the section, teacher and room load checks from step 2, ranked by how far over they are. Nothing in the saved timetable changes.

Step ③ · Generate

Choose what to aim for

  1. Click Aims next to Generate
  2. Switch any of the five soft rules on or off
  3. The score updates at once; Regenerate to aim for the new set

How it’s designed

Each switch is one soft rule written as an aim. Late finish starts off: on 2 CPU cores it makes the solver worse at the other four.

Lattice · 12

A rule that's switched off adds no points and the solver ignores it. The switches travel with the timetable when it's saved online.

Step ④ · View & export

Drag a class to move it

  1. Pick a section, teacher or room
  2. Drag a class card
  3. Green slots are free and show the score change; red ones say why not
  4. Drop it: the class is locked in its new slot

How it’s designed

Every slot is checked against the hard rules during the drag, and the validator checks the whole timetable again after the drop.

Lattice · 13

The numbers on green slots are the score change if the class lands there, so a coordinator can see the cost of a move before making it.

Step ④ · View & export

Lock, regenerate and print

  1. Click a class, then Lock here
  2. Regenerate (keep 1 locked) solves everything else again
  3. Print: add a heading, then one timetable or all sections, one A4 page each
  4. CSV downloads the whole timetable

How it’s designed

Locks keep what’s agreed and re-solve the rest. If the locks make a timetable impossible, the solver says which ones.

Lattice · 14

A locked class shows a lock icon and a thick border. Clear all locks removes them in one go.

Signed in · status line in the header

Save online, keep versions, publish

  1. Sign in with Google or an email link; create an institute
  2. Open the status line → Save online. Each save adds a version
  3. Publish gives a public link that opens without an account
  4. Versions… opens an old version or makes it live

How it’s designed

The database enforces the admin, editor and viewer roles. A save that would overwrite someone else’s asks first.

Lattice · 15

Everything works signed out, saved in the browser; nothing goes online until someone clicks Save online. The last 20 versions are kept, plus the live one. These two shots come from the help pages, made against a test backend.

Signed in · Assistant button in the header

Ask the assistant

  1. Click Assistant and enter a coupon
  2. Ask about the data or the app
  3. Ask for a change: it replies with a card
  4. Apply makes the changes and regenerates; Undo brings back the working copy

How it’s designed

Every card is dry-run in the browser against the hard rules before you see it. Teacher names leave the browser as codes.

Lattice · 16

The assistant runs on Claude through a separate Lambda function. It can propose data edits, moves, locks, aims, regenerating and saving or publishing; deleting, members and roles stay manual. Coupons cap the number of questions per institute.
